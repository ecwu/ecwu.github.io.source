# DGX Spark 三模型固定部署能力测试方案

本版取代之前的推测解码开关、切换后端缓存配置及统一强制启动参数方案。

## 1. 目标与授权

在同一台 DGX Spark 上，比较 Qwen3.8-27B NVFP4、Qwen3.6-35B-A3B NVFP4、Qwen3.8-Flash-Next NVFP4 三套可用部署的性能与容量。统一请求负载和统计口径；后端、加载方式、推测解码和模型特有设置允许不同，必须披露。结果不用于隔离模型架构的因果影响，不评价回答质量，不寻找最优参数。

当前只授权远端完成并保存 Qwen3.6 实验。两个 Qwen3.8 模型必须分别由用户明确启动；不得提供默认连续运行三模型的入口。博客侧本轮仅审核和更新计划，不调用远端服务。远端实施前遵循所在环境的 AGENTS.md。

允许在独占测试窗口内启动目标模型、执行测试、保存结果并恢复原服务。保留原配置和数据；不终止他人任务，不升级系统、驱动、镜像或依赖，不调整全局 swap，不公开实验服务。独占条件不满足时先完成脚本准备并报告冲突。

## 2. 每模型固定一套后端

| 模型 | 拟固定的推测解码 | 加载要求 |
|---|---|---|
| 27B | DFlash2，8 speculative tokens | 沿用已验证方式 |
| 35B-A3B | MTP，3 speculative tokens | 沿用已验证方式 |
| Flash-Next | MTP，4 speculative tokens | 保留必要 PLE disk offload |

三个模型均开启 prefix caching。一套完整配置实际启动、健康检查与短请求验证通过后冻结；recipe 或 dry-run 不是成功运行的证据。记录实际上下文上限、KV dtype、内存预算、调度序列上限、每批 token 预算、分块 prefill、异步调度、后端及回退。262144、FP8、0.8、4、4096 不再是强制共同值，不为形式统一临时组合未经验证的参数。

每个模型从 A 到 C 使用同一个后端进程，不修改启动参数，不切换推测解码或缓存开关。配置无法启动时报告阻塞，不在正式实验内自行调参。预检失败不算正式格子完成。

客户端并发 C 与后端 max_num_seqs 是不同的量。若后端只同时调度一条序列，仍可同步提交 C=2/4 个请求；结果测到的是该固定部署的排队行为。表头显示或可直接展开该上限，不能将排队当成外部污染而剔除。

若实际上下文上限不足，超过该上限的格子标记 unsupported/configured_context_limit，保留实际上限；不自动改成 OOM，也不更改上限后填回同一运行段。

## 3. 请求构造与缓存命中验证

各模型使用自己的 tokenizer 和 chat template，精确输入长度包含模板开销；只裁剪填充材料，保留消息边界和生成后缀。等长 token 不代表相同字节数或完全相同内容。固定材料、任务、生成规则与随机种子，记录实际渲染后的输入构造和 API usage。公开请求编号使用可读名称。

A/C 每条请求、每轮、预热输入都使用独立前缀，将差异放到用户内容最前端。B 组同一对输入完全相同，不同对独立。不能只改变末尾内容。

**预检门槛：独立用户前缀并不保证渲染后的完整输入零命中。** 公共 system prompt 和 chat template 头部也可能形成可复用前缀。正式大矩阵开始前，先验证整个渲染输入的命中情况。若实际后端提供请求级缓存隔离且已核实语义，可以使用：A/C 每条独立，B 每对共用、跨对独立；不得猜测参数、静默忽略参数或重启清缓存。

- cached tokens=0：满足严格无复用条件。
- cached tokens>0：保留并标记 prefix_contaminated，不进入严格零命中汇总。
- 缺少可靠计数：cache_status=unknown，不能按零填补。

usage 为主要依据；服务端增量仅在可归属范围内核对。并发下聚合命中计数不能复制给每条请求。若预检始终不能得到或确认零命中，应先报告 A/C 条件不成立，不继续生成整套必然无效的数据，也不关闭后端缓存绕过。其他满足条件的测试可继续。

计时统一使用客户端单调时钟，同时保留可与遥测对应的墙钟时间。记录接口、模板参数是否生效及 reasoning 解析方式。若 thinking=false 仍返回 reasoning，应标记协议不符，而不是将其当正文。

## 4. A 组：缓存开启、无前缀复用

| 条件 | 设置 |
|---|---|
| 精确输入 tokens | 2048、8192、32768、64512、131072、261120 |
| 客户端并发 | 1、2、4 |
| 正式重复 | 每格三轮，每轮用屏障同步提交 C 条请求；全部结束再开始下一轮 |
| 输出 | 每请求恰好 1024 tokens |
| 请求设置 | temperature=0、ignore_eos=true、thinking=false |

每模型 18 格、126 条正式请求；三模型共 54 格、378 条。不含预热、预检或替换污染轮的补测。请求数是完整可运行矩阵的计划数，失败后不必强凑该数量。

固定数量请求的同步批次吞吐不是持续负载下的最大吞吐。记录各请求提交时间与提交偏差，不把串行提交标作同步。

先确认最长合法输入的 C=1 容量，再按资源状态尝试 C=2/4。不能通过减少输入或输出填补失败格。正式前每格一轮使用独立输入的预热/容量预检，排除于正式统计并记录其耗时与状态。

有效轮要求全部 C 条请求成功、长度准确、usage 可核实、零前缀命中且无外部污染。格子 latency/decode 统计使用有效完整轮中的请求观测；批次吞吐按有效完整轮计算。部分失败轮的成功请求仍保留在明细中，不混入完整轮汇总。

## 5. B 组：前缀缓存复用

沿用同一进程，输入/输出 8192/1024 tokens，并发 1，temperature=0、ignore_eos=true、thinking=false。每模型五对正式请求：首次输入 → 完全相同输入再次请求，共 10 条；三模型共 30 条。

每对内消息与生成参数相同，首次请求完成后紧接重复请求；不插入其他请求。不同对使用独立前缀及独立缓存隔离值（若使用）。首次命中非零或未知的整对不进入严格配对收益汇总，原始记录仍保留。重复请求零命中也是结果，不得只保留有效果的对。

记录每条 TTFT、decode TPS、端到端时延、cached tokens 和可归属指标。首次、重复请求分别显示中位数；收益使用每对 TTFT 差值或比值再汇总，并显示有效配对数。首次 TTFT−重复 TTFT 为等待缩短量，首次 TTFT/重复 TTFT 为配对加速比，负收益或小于 1 的比值同样保留。

“首次”只表示本对前缀未命中，不代表冷模型、冷编译或冷磁盘。不能把观察到的整个时间差无条件解释为缓存唯一造成的因果效果。

## 6. C 组：Thinking 请求参数对照

推测解码保持固定，只切换已核实语义的请求级 thinking 参数。

| 条件 | 设置 |
|---|---|
| 输入 tokens | 8192，包含各档模板开销 |
| 并发 | 1 |
| 档位 | thinking=false / thinking=true |
| 正式重复 | 每档三次，按 false/true 交替执行 |
| 输出 | 上限 1024 tokens，允许正常结束 |
| 其他请求设置 | temperature=0、ignore_eos=false；每条独立前缀，验证零复用 |

C 组明确使用输出预算，不强制填满 1024。两档都允许正常 EOS，实际长度少于预算不算无效。它与 A/B 的固定输出负载不同，必须单独展示，不能混合汇总。每模型 6 条，三模型共 18 条；A/B/C 合计每模型 142 条，三模型 426 条正式请求，实际输出总量不预先固定。

使用同一任务材料，在各自模板下补齐输入长度。这里是等 token 预算的请求对照，不是同一输出量下的纯计算开销测量；正文时延差也不能全部归因于 thinking 的硬件成本。

检查实际模板和流式返回，确认请求参数生效。模型/接口不能切换时标记 unsupported，不调整后端绕过。仅当两档使用同一接口和可靠的字段/解析方式时，比较首正文时间。

分别保存：首个非空生成文本时间（reasoning 或正文任一先到）、首个非空正文时间、reasoning/text 是否出现、API 总输出 tokens、总时延及 finish_reason。role-only、空 delta、usage 事件不触发 TTFT。

只有 API 提供可靠分项计数时才展示 reasoning/body token 数；没有时留空。若 reasoning 在服务端隐藏，无法知道首生成时间，应留空并记录生成文本可观测性，不拿首正文时间代填。若流仅提供未分段文本且无法可靠解析，首正文时间留空。

预算用尽且未出现正文：标记截断和正文未观察到，正文 TTFT=null；不要填 0，也不要把请求成功传输解释为回答完成。正文 TTFT 汇总须显示“观察到正文的请求数/总请求数”，若不足三次则不生成看似完整的三次对照值；明细保留可观测值。

## 7. 指标与状态

| 指标 | 口径 |
|---|---|
| TTFT | 请求开始到首个非空生成文本，包含排队/输入处理等；reasoning 不可观测时留空 |
| 正文 TTFT | 请求开始到首个非空正文；仅在能识别正文时提供 |
| 客户端近似 decode TPS | API 总输出 tokens /（流结束−首个非空生成文本）；包括首包 tokens；时间边界不可观测或分母非正则留空 |
| 端到端时延 | 请求开始到流结束 |
| 同步批次输出吞吐 | 完整成功有效轮的总输出 tokens /（最后结束−最早开始）；先逐轮计算，再求中位数 |
| 完成情况 | 传输完成、长度有效、无污染、正文出现、输出截断、有效轮数分别记录 |

主矩阵 TTFT/decode/时延显示有效完整轮内请求中位数、范围和样本数；不把同轮请求当成独立重复实验，不计算 P95/P99 或显著性结论。SSE chunk 不是 token，不能逐 chunk tokenize 后相加作为准确计数。并发时 Prometheus TPOT 增量没有请求级归属就留空，或只作为明确标注的批次指标。

状态采用分开字段，允许一条记录同时成功传输、输出截断和前缀污染：

- execution_status：ok / oom / timeout / unsupported / invalid / not_run。
- cache_status：zero_hit / reused / prefix_contaminated / unknown。
- external_interference：是否有独立证据的外部负载干扰；自身请求排队不算污染。
- output_truncated、answer_observed、length_valid、included 及排除原因。
- 格子显示 ok / partial / 对应失败状态，附有效轮数和失败分布。

缺失和失败不显示为 0。原始失败保留；有外部污染时补测整轮并记录替换关系，不能因慢就删除样本。

## 8. 生命周期、故障与续跑

每个模型入口完成：独占检查及原服务记录 → 一次启动固定配置 → 参数/模板/usage/短请求验证 → A → B → C → 离线校验与打包 → 恢复原服务并检查响应。

持续采集系统可用内存、swap 换入换出、GPU 温度/设备功耗、队列、抢占、KV 与推测指标。设备遥测不能称为整机插座功耗。不修改全局 swap；发生内存压力时记录并停止受影响格。

每轮超时上限为 1800 秒；超时记录实际观察时长，不把上限当成完成时延参加统计。取消后必须确认队列清空才能继续；确定性 OOM 不在无变化条件下反复尝试。

OOM、进程异常退出、需要重启才能清空的超时终止当前运行段。恢复后使用新的 segment_id，重新预热，保留失败边界。同一配置恢复不是新的配置，但不宣称全程未重启。

A 每格的三轮尽量在同一运行段完成；被故障打断的格保留 partial，恢复后按完整三轮补测并明确替换关系，不能静默拼凑跨段三轮。B 一对必须属于同一运行段，跨段则无效。C 两档跨运行段时，显示边界，不能作同段对照汇总。

单组入口只连接实际配置匹配的实例。若断点续跑后配置改变，创建独立配置标识，不合并到原矩阵。配置未变但跨段的不同完整格可归入同一部署矩阵，明细披露段号。

## 9. 文件与一键入口

```text
configs/backends/{qwen36,qwen38-27b,qwen38-flash-next}.yaml
configs/tests/{performance,prefix-cache,thinking}.yaml
scripts/run-qwen36.sh
scripts/run-qwen38-27b.sh
scripts/run-qwen38-flash-next.sh
scripts/run-suite.py
scripts/validate-results.py
scripts/package-results.py
```

模型参数必须显式指定，缺少时退出并显示帮助，不默认遍历模型。当前只运行 run-qwen36.sh；其他入口等待各自明确授权。

每模型独立结果目录和压缩包。公开包不包含任何 hash、镜像摘要、带提交标识的版本后缀、凭据、私人地址；普通版本、日期和可读编号保留。完整身份信息仅留远端私有记录。

- protocol.md、environment.json、configs/：实际协议、冻结配置、后端差异、实际模板/接口/usage能力，不用 dry-run 冒充实测。
- runs.jsonl：模型、配置标识、segment_id、实际启动/结束时间、重启原因、预热和恢复结果。
- requests.jsonl：实验组、thinking 档位、模型、配置、段号、格/轮/配对/请求编号、实际输入输出、输出预算、cached tokens、计时边界、各指标、reasoning/正文可观测性、结束原因、各状态、排除/替换关系。
- rounds.jsonl：同步批次起止、提交偏差、计划/实际请求数、有效性、总输出、吞吐及故障。B 另存 pairs.jsonl；C 保留档位与重复编号。
- request-events/、telemetry/：流事件、指标与定义，不混入真实用户内容。
- matrix.json：每模型完整 18 个 A 格，包含未运行与失败；B/C 对应汇总。跨模型合并展示时，未授权模型明确为 not_run/not_authorized，不伪造结果。
- validation.md、README.md：计数、长度、公式、污染、完整轮、配对、运行段检查、失败范围、耗时及原服务恢复结果，不附校验值。

## 10. 博客的一张交互矩阵

只有两个主要 dropdown：实验（缓存开启、无前缀复用 / 前缀复用 / Thinking 对照）和指标。删除推测解码开关，三模型固定配置在列头附近说明。

- A：六档输入为行；三模型各有 C=1/2/4 三列。指标为 TTFT、近似 decode TPS、同步批次吞吐、端到端时延、完成情况。客户端并发与后端调度上限同时可见。
- B：首次、重复为行，三个模型为列；可切换 TTFT、decode、总耗时、缓存命中及配对收益。收益视图行显示配对等待缩短量或配对加速比，避免将收益硬填到“首次”行。每格注明有效配对数。
- C：thinking 关闭/开启为行，三模型为列；指标可选首生成文本 TTFT、首正文 TTFT、近似 decode、端到端、实际输出 tokens、完成/截断情况。这里不展示无意义的并发吞吐排名。

每格显示值/单位/有效样本数，点击或键盘展开范围、逐请求、轮次、运行段与失败原因。整表共用色标，切换指标同步更新；缺失、污染、失败、截断有文字标识。窄屏固定行头并横向滚动，不能缩小成不可读字体。未执行的两模型先留明确占位。

## 11. 历史结果归档

旧配置和旧请求不自动进入新汇总。只有固定后端配置、模板与请求构造、缓存条件、指标口径及可追溯运行段全部匹配，才可考虑复用，并披露来源；缺证据默认归档。

用户报告此前新采集批次使用过 prefix caching 关闭或推测解码关闭，这些批次不属于本方案。此前交给博客的 9 月 19 日历史证据包则记录了 prefix caching 开启及 MTP=3；不要把所有历史数据笼统标成缓存关闭。它仍然不能仅凭这两项一致就直接纳入新实验。

待新包完成核验，再整体替换博客旧图、旧性能表、旧数值结论和下载数据；不提前用规划值改写实测结果。保留仍有依据的部署介绍，继续用实际观察推进正文，不堆砌运行身份标识。
